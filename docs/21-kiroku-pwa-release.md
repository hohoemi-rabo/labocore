## Service Worker を入れない理由

`/kiroku` は `(kiroku)/layout.tsx` で `force-dynamic` を明示してまで「毎回サーバーに問い合わせる」ことを保証している画面で、**期限切れのお知らせを消す**・**過去日の次回を隠す**という要件がリクエスト時刻に依存して初めて成立している。ここに SW のキャッシュを挟むと真っ先に壊れるのがその保証で、生徒の端末に古いお知らせが貼り付き、しかも管理側からは消せない（生徒向けは anon で読むためミューテーションが起きず `revalidatePath` も効かない）。合言葉 Cookie は1年で失効し `KIROKU_PASSWORD` を変えれば即時失効する設計なので、授業記録を SW キャッシュに残すと「失効後も読める」という別の穴になる。インストール可否の面でも問題はない（Chrome は 108/112 以降、fetch ハンドラを持つ SW をインストール要件から外している）。**得るものが無く、失うものが要件そのもの**。

## ⚠️ 仕様として受け入れること（調査で判明）

### iPhone は「ホーム画面から開いた初回」に合言葉をもう一度聞く

iOS のホーム画面 Web アプリは **Safari と Cookie の保管庫が分かれている**。Safari で合言葉を入れてから追加しても、アイコンから開いた初回は合言葉とクラス選びをやり直すことになる（2回目以降は覚える）。回避策は Service Worker を要し、上記の理由で入れない。**Android は引き継がれる。**

→ もとの完了条件「合言葉 Cookie が引き継がれること」は iOS では成立しないので、**「Android は引き継がれる／iPhone は初回だけ再入力」**に読み替える。案内文にも書く。

### LINE のアプリ内ブラウザからは「ホーム画面に追加」ができない

URL を LINE で配る以上、**これが M1 で最も高確率の失敗要因**。iOS は「Safariで開く」、Android は「Chromeで開く」を先に押してもらう必要がある。案内文の**冒頭**に置くこと。

### アイコンはお披露目の前に確定させる

差し替え自体は SVG → `npm run icons` で済むが、**iOS はインストール済みのホーム画面アイコンを更新しない**（生徒さんが削除して追加し直す必要がある）。Android は数日で自動的に貼り替わる。「とりあえず仮アイコンで配って後で差し替える」は避ける。

### Android（Chrome）

1. LINE のリンクを開いたら「Chromeで開く」を押す
2. あいことば → クラスページまで進む

5. 起動直後のスプラッシュが黒地＋アイコンか。上のステータスバーが黒いか
6. アイコンが丸や角丸に切り抜かれたとき、**笑顔が欠けていない**か
7. 横に倒しても縦のままか
8. **クラスタブ**: 水曜午後を登録すると6個になり右端が少し切れる。横になぞってスクロールできるか

11. 文字を指で広げて（ピンチ）大きくできるか

### iPhone（Safari）

1. LINE のリンクを開いたら「Safariで開く」を押す
2. あいことば → クラスページ
3. 共有 →「ホーム画面に追加」。**アイコンが白い四角や虫めがねになっていない**か、名前が「授業の記録」か
4. アイコンをタップ → URL バーが出ないこと
5. **あいことばをもう一度聞かれるのは正常**。入れ直して、2回目以降は聞かれないことを確認
6. 画面いちばん上の**時計・電池がヘッダーの文字と重なっていない**か。下端の横棒が「クラスをえらびなおす」に重なっていないか
7. 9〜11 は Android と同じ
